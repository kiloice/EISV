# 最终落位：不变量、优先级与复盘

本文记录 `finalPlacementPose` 的物理约束与 2026-08 落位改动复盘，供以后改求解逻辑时先对文档再动代码，避免再在特解之间横跳。

相关代码：`eisv-core.js` → `createSpace2D` → `finalPlacementPose`；烟测：`tests/solve-smoke.mjs`。

---

## 1. 需求与优先级（固定）

按优先级从高到低：

1. **不穿模**（`validPose` / 严格底边与台面下方禁入）
2. **有退台则落台或斜担，禁止吸顶**（`mode !== "top"`）
3. **双侧支撑**（几何上做得到时：浅侧内角 + 深侧台面）
4. **开口对中**（在 1–3 的可行域内 `min |cx − 开口中心|`）
5. 其它观感

新增需求时先标明插入哪一档，以及是否会取消某一档的自由度。

---

## 2. 分层语义（`mode`）

| mode | 条件 | 行为 |
|------|------|------|
| `top` | 左右退进皆为 0（直壁） | 吸顶；`x` = 开口中心 |
| `step` | 有退台且左右等高，或无法斜担 | 水平落在较矮（或等高）退台；`x` 优先开口中心 |
| `bridge` | 有退台且左右不等高，且件长足够 | 斜担；见下节 |

**硬规则：** 只要存在退进（`leftInset` 或 `rightInset` > 0），fallback **只能是 `step`，禁止 `top`**。  
把失败塞进吸顶会把「悬空」与「斜担错误」混在一起，调试失真。

---

## 3. 不等高斜担不变量（bridge）

坐标：`y = 0` 为腔顶，向下为正。左台顶 `y = leftHeight`、`x ∈ [0, entryLeft]`；右台顶 `y = rightHeight`、`x ∈ [entryRight, topWidth]`。

### 3.1 支撑点

- **浅侧触点 S**：必须在**浅侧内角**（左浅则为 `A = (entryLeft, leftHeight)`，右浅则为 `B`）。  
  原因：斜直线若浅侧触点落在台面内侧（非内角），线段会切入浅侧台面实体。
- **深侧触点 D**：在深侧台面顶上滑动（自由度）。
- 底边同时包含 S 与 D；`|SD| ≤ L`（零件底边长）。

### 3.2 多余长度

- `t = L − |SD|` 只允许伸向**浅侧空腔**（沿底边离开深侧的方向）。
- 禁止沿底边越过深侧触点再伸入深侧台面下方（会穿台）。

### 3.3 自由度与对中

- 每个合法 D 对应**唯一**位姿（S 固定、t 由 L 与 |SD| 决定）。
- 在深侧台面线段上扫描 D → 得到候选族 → `validPose` 过滤 →  
  **`argmin |pose.x − openingCenter|`**。
- **禁止**把零件左（或右）端钉死在内角当唯一 seed：那会杀掉对中自由度，表现为「角点对角点」。

### 3.4 实现形态（保持）

```text
candidates = 参数化深侧触点 D（有界扫描）
filter 外壁 / 宽松 validPose
按 |cx − oc| 排序
对前若干名做 strict validPose
return 第一个通过者
else fallback → step（矮台 + 对中）
```

不要再叠「方案1 钉端 + 方案2 双台 + 方案3 AB + prefer 分档」多主路径。

---

## 4. 改动检查清单

改 `finalPlacementPose` 或碰撞相关时：

1. 对照本文 §1–§3，确认未破坏不变量与优先级  
2. `node tests/solve-smoke.mjs`（含 bridge 对中、窄退进、有退台非 top）  
3. `node scripts/assemble.mjs`  
4. 浏览器确认标题版本号；必要时 dump `#part` 的 `transform` 或截图  
5. 动画终点须用 `finalPlacementPose`，不信任路径网格末点  

建议锁定的用户几何（烟测已部分覆盖）：

- `240 / 20+20 / h40·55 / 220×20` → `bridge`，`|cx − 120|` 小  
- `240 / 10+30 / h40·55 / 220×28` → `bridge`，跟随开口中心 ~110  
- `240 / 50+30 / 200×20` → 开口中心 ~130  
- 有退台且件长短于斜跨 → `step`，非 `top`

## 5. 复盘：为何曾绕很多路（2026-08）

### 5.1 先写代码、后补物理

未先写清自由度与禁止态，而是轮流实现「看起来像坐下」的特解：深侧钉死、两端落台、AB 共线、再 fallback 吸顶。每次修症状，约束系统未闭合。

### 5.2 优先级未写死

「不穿墙 / 双侧碰到 / 不吸顶 / 对中 / 角点接触」轮流当唯一真理，修 A 毁 B。

### 5.3 特解当成解空间

单个 seed 公式没有候选族，对中在数学上不可做，却被误判为「对中与落台不可兼得」。

### 5.4 `top` 当失败垃圾桶

bridge 失败 → 吸顶 → 用户统一描述为「悬空水平」，无法区分根因。

### 5.5 验证偏 node、轻浏览器

core 已 `bridge` 但 HTML 未组装、缓存旧文件、动画末帧网格误差，造成「你确定改了吗」。

### 5.6 采样密度冒充物理

用加密采样掩盖「几何上本不该那样支撑」；台面下方禁入应是规则，不是把 `n` 调到 60。

### 5.7 补丁叠加无停损

同一函数堆多方案后，静默走到另一支。教训：**两轮补丁仍不稳 → 停写，重写不变量与单主路径**（后期重写后才稳定）。

### 5.8 以后规避（一页纸）

```text
1. 先写：支撑几何、禁止态、目标函数、fallback
2. 参数化可行域（DOF），禁止唯一 seed 当主路径
3. filter 碰撞 → optimize 对中
4. 有退台禁止 top fallback
5. 测试锁定用户几何 + 对中误差上限
6. 组装版本号 + 浏览器确认 transform
7. 两轮补丁仍歪 → 重写结构，不叠第三层 if
```

## 6. 与路径搜索的边界

- **最终落位**只由 `finalPlacementPose` 定义语义（支撑 + 对中）。  
- **路径搜索**用网格 BFS 找从入口到「最终位姿邻域」的可行路径；末点应写成 `finalPlacementPose` 的结果，UI 动画结束亦应吸附该位姿。  
- 不要在 BFS 里重新发明落台规则。
